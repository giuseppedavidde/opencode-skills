opencode-skillsworkflow explanation
Sections

    Overview

    One router reads every request. It classifies the request and delegates it to one specialist. The specialist returns an answer with a verification block. A gate checks that block before the router summarizes.

    1 · Classify

    Router model: opencode-go/deepseek-v4.1-flash#low. It reads, decides and delegates. The edit and write tools are denied.

    2 · Delegate

    10 specialist subagents, one built-in explore agent and the primary router. Each specialist has its own model and step budget.

    3 · Verify

    verifica-gate requires a ## VERIFICA block. Below 85, the router adds a caveat, retries once, or asks you.

    Three surfaces

    • opencode is the source of truth: agents/, skills/, command/, plugins/, config/.
    • VS Code is generated by install-vscode.py into ~/.copilot/.
    • install.sh links the opencode layer and runs both installers. It is idempotent.

    Suggested reading order

    1. Architecture & Layers — where the files live.
    2. Routing Decision — the priority ladder, rungs 0 to 9 plus 4b.
    3. Scenario Explorer — start here when you only want the behavior.

    Routing Decision

    The ladder is ordered. The highest strong signal wins, even when lower-category keywords are also present. Priority 0 is the top rung.

    1. 0
      PDF / attached document → pdf_reader

      Wins over everything. Three exceptions: "compress or optimize a PDF" uses the pdf-compress skill; "build a graph from a document" is rung 3; "generate a skill from a book" is rung 6.

    2. 1
      ÖGK / Austrian health insurance → oegk_health

      ÖGK, Gesundheitskasse, Krankenkasse, Kassenleistung, Wahlarzt, Rezeptgebühr, Selbstbehalt, Blutbefund, Labor, Sonografie, MRT, CT, Röntgen, Facharzt, Zuweisung, "was zahlt die Kasse", "quanto pago". Loses to an attached PDF and to coding.

    3. 2
      Explicit trading → trade

      Tickers, options, call/put, strike, greeks, delta/gamma/theta/vega, expiry, DTE, roll, hedge, "analizza <ticker>", "strategia opzioni", market scan, VIX/DXY/Fed. Always delegate when the user asks to ANALYZE a ticker, position or option. Loses to a BUILD or MODIFY CODE intent: the action verb decides.

    4. 3
      Explicit graphify → graphify_helper

      graph, grafo, knowledge graph, "mappa del codice", build graph, path between, explain node, community detection, god nodes. Wins even when the text mentions code.

    5. 4
      Explicit coding → coder

      implementa, refactor, modifica, debug, fix, tests, backtest, "nel mio codice", "nel file X", "nuovo script". Generic verbs (write, create, add) count only with a code-ish object: script, module, function, class, file, test, API, library, plugin, app, algorithm, or a code extension. Coding intent wins over ALL strong trading words.

    6. 4b
      VS Code extension → vscode_ext

      vscode extension, estensione vscode, vsix, vsce, contributes, activationEvents, webview panel, TreeView, language server, publish extension. Wins over generic coding.

    7. 5
      Explicit skill update → skill_updater

      "aggiorna skill", "update skill", "sync skill", "submodule update", or a specific skill name plus an update verb.

    8. 6
      Explicit book-to-skill → book-to-skill-agent

      "converti libro", "crea skill da libro", "skill da pdf/epub", "generate skill from book".

    9. 7
      Generic trading keywords alone are not enough

      portfolio, price, scan, market, position, strategy, buy/sell, entry/exit, IV. The surrounding intent decides.

    10. 8
      Web research → the router handles it

      "cerca su web", "web search", oil, gold or gas price. Exception: when the target is a ticker or an option, rung 2 applies.

    11. 9
      Simple tasks → the router handles them

      Explain code, read a file, find a definition, chat, math, config checks. Short answer of 1–3 lines.

    Ambiguity rule

    When two strong categories conflict, the router asks ONE clarifying question BEFORE delegating. It never guesses with an expensive call.

    Planning threshold

    Ask coder_planner when the task touches 2 or more files, or needs more than 20 lines of new logic.

    Ticker look-alikes

    A project name that looks like a ticker is not a ticker. Example: IBKR_Trading alone does not trigger rung 2.

    Request Lifecycle

    End-to-end trace from the user message to the final summary.

    1. User message reaches the router

      Router model: opencode-go/deepseek-v4.1-flash#low.

    2. The router scans signals top-down

      First strong match on the priority ladder wins.

    3. Two strong categories conflict

      The router asks ONE clarifying question before any delegation.

    4. The router checks independence

      Independent objects of the same category allow up to 4 parallel Task calls in one message.

    5. The router builds the subagent prompt

      Goal, context and constraints. It includes the context-store hash path when content was compressed.

    6. The subagent runs its own loop

      Loads skills, calls MCP tools (trading_*, headroom_*), runs bash/read/edit, and may re-delegate. Example: trade → coder. In opencode only, depth 3.

    7. The subagent returns the answer and ## VERIFICA

      Both go in the same message: confidenza, evidenza, non_verificato, escalation_consigliata. Never footer-only.

    8. verifica-gate inspects the final message

      Allow, allow plus log, or block. It also anchors confidence to real shell exit codes and prunes long task output.

    9. The router applies the confidence thresholds

      85 and above, 60–84, 40–59, or below 40. Each band has its own action.

    10. The router summarizes in 1–3 lines

      It adds one caveat sentence when confidence is 60–84.

    Verification Gate

    Every subagent answer must carry a ## VERIFICA block. The router turns the confidence value into an action.

    ConfidenceBandRouter action
    >= 85highSummarize normally.
    60–84mediumSummarize plus one caveat sentence: "Confidenza media: <reason from non_verificato>".
    40–59lowRe-delegate ONCE to the same subagent: "your previous answer had confidence X/100, reason: <non_verificato>, check and correct, then fill VERIFICA again". Then summarize with a caveat.
    < 40 or no blockunverifiedONE clarification question to the user: "I dati non sono verificati: vuoi che ri-deleghi a @coder …?". Yes → re-delegate to coder. No → summarize with a caveat.

    Gate decisions on the final message

    1. VERIFICA block present → allow.
    2. Long message (600 characters or more) without a block → allow and log missing_verifica_soft.
    3. Short message (fewer than 600 characters) without a block → block and ask for the COMPLETE answer.
    4. Footer-only reply (fewer than 300 characters) after a long answer → allow and log verifica_only_followup.

    Exit-code anchoring

    • Confidence is anchored to the real exit codes of shell commands.
    • Per task, the last outcome wins.
    • Inline snippets are never anchorable.
    • Very long task output is pruned before it reaches the model.
    • Audit trail: ~/.config/opencode/stats/gate_events.jsonl. Write-only by design.

    Parallel Delegation & Orchestration

    Parallelism is limited and deliberate. Mixed categories never run as two parallel tasks.

    Router limits

    • Maximum 4 parallel tasks per message.
    • Only truly independent objects.
    • Same category only.
    • Mixed categories go through the ambiguity question or the priority ladder.

    smart-dispatcher skill

    Turns natural language into four phases:

    CLASSIFY → BUILD → DISPATCH → AGGREGATE

    Example input: "scan di italy, germany e francia top 5".

    subatomic-orchestrator skill

    • DISCOVERY: read orchestrator: from frontmatter, or infer it.
    • DECOMPOSITION: split_by ticker|market|file|chapter|query, then chunk_size and parallel_batch.
    • DISPATCH: task tool for small chunks, @agent for large ones.
    • AGGREGATION: rank|concat|json_merge|none, then sort, dedup, top_n.

    VS Code limitation

    A subagent cannot start another subagent in VS Code. The top-level agent runs each chain step by step.

    In opencode, re-delegation is allowed to depth 3.

    Plugins, MCP & Token Economy

    Five plugin folders load through the anchor link. Large tool output is compressed before it reaches the prompt.

    auto-headroom

    • Intercepts tool output of 800 characters or more: bash, read, grep, glob, webfetch.
    • Skips trading_* payloads and targeted context-store retrieval.
    • Saves the raw text to ~/.config/opencode/context-store/<hash>.txt plus <hash>_index.json.
    • Returns a compressed preview and the hash. Retrieve with /read-chunk or the headroom MCP.
    • Saves up to 90% of prompt tokens.

    graphify

    Injects a knowledge-graph reminder before shell calls when a graph exists.

    routing-stats

    Records each subagent delegation and VERIFICA block as JSONL in ~/.config/opencode/stats/routing_events.jsonl. Read it with /routing-stats.

    tokens-per-second

    Subscribes to session.step.started and session.step.ended, measures duration in ms, appends JSONL stats.

    verifica-gate

    Enforces VERIFICA, anchors confidence to exit codes and prunes task output. Audit: ~/.config/opencode/stats/gate_events.jsonl.

    Install & VS Code Layer

    install.sh is idempotent. Rerun it after git pull or after moving the repository.

    Stages

    1. Submodules.
    2. opencode symlinks.
    3. MCP runtimes: setup-headroom.sh, setup-trading-mcp.sh.
    4. VS Code layer: install-vscode.py --target user.

    Flags

    FlagEffect
    --dry-runPrint the plan, change nothing.
    --forceBackup first to ~/.cache/opencode-skills/backup/<timestamp>/.
    --no-mcpSkip the MCP runtimes.
    --no-vscodeSkip the generated VS Code layer.
    --with-reaInstall the rea MCP as well.
    --with-systemdInstall the user service units.
    --yesAccept prompts without asking.
    No machine paths

    Configuration uses {env:HOME} placeholders plus the anchor link. A moved repository keeps working after a rerun.

    Secrets

    config/secrets.env.enc is decrypted by scripts/decrypt_secrets.sh.

    Writing directive

    ASD-STE100 applies to every agent: maximum 20 words per sentence in a procedure, 25 in a description, active voice, numbered vertical steps, exact numbers with units. The VERIFICA block follows the same rules. Conformance: scripts/ste_conformance.py with --wiring, --self-test, directory lint and --strict.

    Glossary

    TermMeaning
    RouterPrimary agent. Classifies the request and delegates. Cannot edit or write files.
    SubagentSpecialist that executes one delegated task in its own context.
    Priority ladderOrdered list of signals. The highest strong signal wins.
    Strong signalAn explicit category marker: an attached PDF, a ticker, "knowledge graph", a build verb with a code object.
    Ambiguity ruleTwo strong categories conflict → one clarifying question before delegation.
    Atomic planNumbered, single-action steps with acceptance checks, produced by a planner agent.
    VERIFICARequired block: confidenza, evidenza, non_verificato, escalation_consigliata.
    ConfidenzaSelf-assessed confidence, 0–100, anchored to real command exit codes.
    EvidenzaThe commands executed and their pass/fail result.
    Non verificatoWhat could not be checked. It feeds the caveat sentence.
    EscalationRecommendation to involve a stronger model or a human when risk is high.
    Gateverifica-gate plugin and hook that validates the final message.

    Anchor linkStable symlink opencode-skills that points at the repository.
